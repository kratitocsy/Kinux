# Contracts

The shared formats every part of Kinux speaks: the run server, the workers, the viewer, the MCP server and the extension. They are JSON Schemas (draft 2020-12), validated with Ajv.

Version 1. The event envelope is frozen. Types may gain optional fields, but required fields do not change within v1. A change to a required field is a new version and needs an approved pull request.

| File | What it defines |
|---|---|
| `event.schema.json` | One line of a run's `events.jsonl`: an envelope plus the data of each event type |
| `manifest.schema.json` | The design files and artifacts of one run, each with a hash |
| `receipt.schema.json` | The evidence receipt: hashes of inputs, tool versions and seeds, plus the score |
| `check-run.mjs` | Validation functions and the rules a schema can't express |
| `fixtures/` | A sample run (`valid-run.events.jsonl`, `valid-run.manifest.json`), generated by `make-valid-run.mjs` |

**The sample run is entirely synthetic.** No solver produced it, and every event in it says `provenance: synthetic`. It exists to define the format and to test the rules.

## The envelope

Every event has `v`, `run_id`, `seq`, `ts`, `type`, `actor`, `design_hash`, `provenance` and `data`.

- **`seq`** starts at 0 and has no gaps. The server assigns it. It is also the SSE event id, so a client can resume.
- **`actor`** is who did it: `human`, `builder`, `villain`, `solver` or `system`, plus an id.
- **`design_hash`** is the hash of the design version the event is about. A result whose hash is older than the current design is stale.
- **`provenance`** is `real`, `recorded` or `synthetic`. The UI must always show it.

## Rules

These are enforced by `checkRun` and tested in `tests/contracts.test.mjs`.

1. Verdicts are `PASS`, `FAIL`, `NOT_CHECKED` or `ERROR`. `NOT_CHECKED` and `ERROR` need a `reason_code`.
2. **A mutant is killed only if the baseline passed the check and the mutant failed it.** `NOT_CHECKED` and `ERROR` never kill.
3. `killed_by` is non-empty exactly when the status is `killed`.
4. A mutant marked `survived` has no check that failed on it.
5. Every result belongs to a test that was queued first.
6. **Score** = killed / (killed + survived). `NOT_CHECKED`, `ERROR` and `equivalent` mutants are reported separately and never counted. Score is `null` when nothing was checkable.
7. **Checkable fraction** = (killed + survived) / total mutants. The score always travels with its checkable fraction, the mutant count, and a Wilson 95% confidence interval.
8. `run.started` is first, `run.finished` is last, and a completed run with mutants has exactly one `run.score`, after the last mutation result, matching the results.
9. Every receipt carries the fixed disclaimer: pre-check linter, not a certification.

## Check a run

```js
import { checkRun } from './contracts/check-run.mjs';
const problems = checkRun(events); // [] means consistent
```

## Open items

- The design graph, mutant and check definitions are not here yet. They arrive with the mutation engine, so they match what it needs.
- Receipts are not signed in v1.
- The license for these schemas is not decided. The plan suggests a permissive one so other tools can emit receipts.
